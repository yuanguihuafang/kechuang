# 重排服务超时与失败处理

## 决策

远程重排请求的 HTTP 客户端超时从 5 秒提高到 60 秒，避免重排服务在较慢响应时过早失败。超时仍为服务端代码固定值，不新增环境变量。

重排服务调用失败（包括超时、HTTP 错误或无效响应）时，检索使用重排前的候选及其原始融合分继续排序并返回；响应中的 `rerank_applied` 标记为 `false`，不得将回退结果标记为重排成功。该分数是 Milvus 混合检索后的融合分，不是重排模型分数；回退结果的排序质量可能较低。显式关闭重排仍按调用方配置处理。

企业/专家画像检索统一通过 Retrieval 向量检索，不再由内部身份直接查询 MySQL 并单独调用重排。内部身份不指定固定 scope，由 Retrieval 根据身份计算可访问范围；外部身份限定 `public` scope。这样两类身份共用向量召回、重排及其失败回退逻辑。

## 范围

调整 Retrieval 的远程重排 HTTP 请求超时及服务调用失败时的结果处理；企业/专家画像统一走 Retrieval 向量检索。用测试锁定行为；不修改召回数量、重排输出数量、重试策略或其他模型服务超时。
