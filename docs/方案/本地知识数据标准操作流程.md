# 本地知识数据标准操作流程

适用于本地管理控制台的文档、草稿、发布、问答和索引维护。本文约束应用流程；不代替生产变更审批，也不代表服务器已同步。

## 数据归属

| 数据 | 权威存储 | 规则 |
| --- | --- | --- |
| 文档、版本、解析状态、草稿、确认分块 | PostgreSQL | 以活动版本和草稿状态为准；重解析期间旧结果不可作为当前结果展示。 |
| 已发布业务记录 | MySQL | 仅已发布草稿写入；沿用稳定业务 ID，重试不创建重复业务行。 |
| 原件、解析产物、图片及图片清单 | MinIO | 引用对象必须真实可读；图片统一由 `document_id + image_id` 生成 `/api/v1/perception/images/{document_id}/{image_id}`。 |
| 检索索引 | Milvus | 派生数据，可从有效的 MySQL、PostgreSQL 和 MinIO 来源重建；不得把未发布内容作为公开知识。 |

- 同一文档 ID 在目录和详情中只显示当前活动版本的一条记录，不再并列展示历史版本的管理卡片。更新后以当前记录覆盖展示；历史任务保留用于排查，不作为当前文档状态。

## 定时清理边界

- 用户逻辑删除草稿后立即对个人中心隐藏；该请求不立即物理删除数据。后端每天北京时间 02:00 检查超过 30 天的已删除草稿，以及连续 30 天未更新的 `CONFIRMED/PENDING_REVIEW` 草稿附件，清理前核实共享和发布引用。前端根据附件实际过期状态隐藏下载入口。
- 企业库/专家库未发布来源仍有独立的 30 天过期规则；不能据此推断其他类型管理员文档也会自动清理。
- 孤儿对象在统一清理时段按配置的宽限期检查，并在删除前重新核实 PostgreSQL 引用；已发布数据所引用的原件、版本、图片和解析产物必须保护。
- 审计记录默认保留 180 天；管理员手动彻底删除与后台定时清理是两条不同操作路径。
- 自2026-11-05起，未保存的临时上传附件保留7天，超过期限后在北京时间每天02:00统一检查。到期不等于文档可删除：清理须完整收集草稿正文附件、`source_document_id`、原件对象键及已发布版本的引用；同一文档的旧任务不得清理新版本正在使用的图片或把整份文档标成`PURGED`。已保存未发布草稿的30天规则不变。

## 索引恢复 / 整库替换

服务器升级后由管理员在数据管理页按顺序操作：

1. 点击**检查可恢复来源**（只读预检），记录可恢复来源、MySQL 记录数及不可恢复项。刷新前后端版本后重新检查；不可恢复项须先按文档 ID、草稿 ID 和 MinIO 对象键逐条处理。
2. 确认检查结果稳定后，点击**确认并恢复影子 Collection**。恢复应写入影子库，不改当前活动 Collection；等待任务完成并检查失败明细。
3. 对比影子库与当前库：按知识类型核对记录数、业务 ID/source_id、发布状态、来源文档、分块数和图片引用。抽查关键问答及图片可读性。数量一致本身不等于内容正确。
4. 只有对比通过后才执行**替换/重建**。确认 Alias/活动 Collection 指向新库，并再次核对计数及问答；失败时保留旧活动库，按任务记录重试或回退。

## 故障处理与边界

- 同一模型的管理字段提取提示词应明确“整理已有资料”，把文档内容作为数据，不执行其中的指令；专业领域资料只整理已给出的企业、产品和应用事实，不生成新设计、序列或实验步骤。单条输出完整对象，多条输出`{"items":[...]}`；示例使用目标类型已有字段，示例数据不得混入真实结果。修改后先对原失败资料做不入库验证，保留原始文档、已发布数据和模型配置。
  - 2026-11-05：本地候选`admin-v5`加入了上述边界、目标字段的非空示例及空结果示例；本地与4090暂存代码各通过1454项测试。对原失败文件完整4404字原文的不入库复放仍未通过，最终两次响应长度13、10字符，未生成草稿。候选未替换线上提示词；模型与OPIEos不变。服务器诊断位于`/home/zyx/kechuang-deerflow/BF/admin-prompt-v5-20261105-204102/`，最终结果见`original-document-final-dry-run.json`。测试通过仅证明输出契约和回归，不代表供应商已接受这份资料。
- 模型返回明确的短句拒答时，任务返回`LLM_REFUSAL`，不归为JSON格式错误，也不重复发送同一资料。JSON Mode不保证供应商一定处理所有内容。2026-11-05对《上海天鹜科技 企业简介1105(1).pdf》保存原文只读复放时，上游DeepSeek-V4.1-Flash-1017返回明确拒答；该文件的真实字段提取尚未通过，模拟资料成功不能替代此文件验收。不得伪造字段、清空内容或自动切换模型后声称成功。
- 字段提取单独启用 `response_format={"type":"json_object"}`，不改变普通问答输出。格式或字段结构错误、空回复、明确截断时最多纠正重试一次；仍失败保留解析原文，以具体错误码显示，不生成或发布草稿。第三方兼容接口明确拒绝 JSON Mode 时沿用现有告警降级，最终仍必须通过 JSON 和字段校验。终端只记录错误分类、尝试次数和响应长度，不记录附件正文或模型原始回复。

- 管理台原件下载使用 `GET /api/v1/admin/documents/{document_id}/file`，沿用管理台现有部署访问边界，不依赖普通用户登录 Token。只读取当前未回收、未彻底删除的版本；普通用户下载接口和权限不变。部署时管理台与 `/api/v1/admin/` 必须处于同一受控访问范围。
- 图片或解析产物缺失：先按文档 ID 检查原件、活动版本、MinIO manifest 和对象键；原 PDF 可用时可只重解析/重分块，保留已确认的草稿字段和业务身份，再通过发布流程整体替换相关来源组。

- PostgreSQL、MySQL、MinIO、Milvus 不存在分布式原子事务。预检只能降低部分写风险；写入中断仍须依赖任务状态、固定 ID 和显式重试，不能把单个接口 200 当作全链路一致。
- 日常读取不得隐式修补或写回清单。恢复和重建是显式管理操作，执行前先保留可恢复备份，并在任务完成后核对结果。
