# 问答与个人中心 API

API 根地址按开发/测试/正式环境配置；本文中的 `/api/...` 均为相对路径。小程序正式环境必须使用已配置的 HTTPS 合法域名，不要把服务器地址写死在页面代码中，也不要把 `/api/...` 路径放进根地址。

当前服务器接口浏览器（仅开发参考）：[Swagger](http://27.223.9.106:8793/docs) · [ReDoc](http://27.223.9.106:8793/redoc)

除登录外，受保护的业务请求携带：

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

上传使用 `multipart/form-data`。身份来自登录 Token，业务请求不传 `user_id`；用户 ID 均为字符串。

文件上传仍限制单文件50MB；后端已取消固定50页门槛，前端不要另行拦截超过50页的文档。解析排队和超时规则不变，失败按接口返回的错误展示；第三方解析服务自身限制不等于平台仍有50页限制。4090服务器已于2026-11-05 13:42同步并重启生效。

不支持的文档统一返回`UNSUPPORTED_FILE_TYPE`，应直接展示后端转换提示：`.doc → .docx`、`.ppt → .pptx`、`.xls → .xlsx`，提示用户用对应软件另存为，不能只改后缀。问答同步材料解析返回HTTP415，读取`error.code/error.message`；流式解析的HTTP200不代表成功，`error`事件包含数字`code=415`、`error_code=UNSUPPORTED_FILE_TYPE`、`stage=upload`和`message`，收到后停止等待，不继续处理草稿、不自动重试。管理台上传HTTP202失败体读取`status=FAILED`和`error_code/error`。完整响应示例见[文件格式错误契约](../前后端API接口文档.md#14-不支持的文件格式)。音频仍按原有语音流程处理，支持格式及单文件大小限制不变。

先上传资料、后选择用途时，后端在创建/保存草稿时补齐附件的空知识类型，发布时也会校验补齐；有效文件无需重新上传或解析。原件归属、版本、路径或已有分类冲突仍会阻止发布并返回HTTP409，前端直接展示原因。

小程序只调用科创业务 API，不直接访问 DeerFlow、MCP、数据库或 MinIO。问答使用支持流式响应的网络请求实现消费 SSE；`chunk` 边界不等于 SSE 事件边界，必须按空行组帧并按 UTF-8 增量解码。`token` 追加到当前助手消息，`progress` 更新进度，收到 `done` 才按 `done.result` 合并最终卡片和动作；不能把 `done` 再作为第二条助手消息追加。断流且没有终态时先读同一会话历史，不自动重发问题。

## 1. 登录与个人资料

| 接口 | 请求参数 | 响应 |
|---|---|---|
| `POST /api/v1/auth/login` | JSON：`user_id` 必填 | `{authenticated, mode, access_token, expires_in, user}` |
| `GET /api/v1/auth/me` | 无 | `{authenticated, mode, user}`，不重新签发 Token |
| `POST /api/v1/auth/logout` | 无 | `{authenticated:false, mode:"test"}` |
| `GET /api/v1/me/profile` | 无 | 个人资料对象 |

登录请求：

```json
{"user_id":"211624786494580925"}
```

登录响应示例：

```json
{
  "authenticated": true,
  "mode": "test",
  "access_token": "<access_token>",
  "expires_in": 43200,
  "user": {
    "user_id": "211624786494580925",
    "name": "王军",
    "company": "示例公司",
    "phone": "13800000000",
    "is_inner_user": false,
    "user_type": "1",
    "user_role": "external"
  }
}
```

`user_role`：`external` 外部用户、`internal` 内部用户。当前 `mode=test`；实际有效期以 `expires_in` 为准。

除登录外，身份以 `Authorization: Bearer <access_token>` 为准。不要把 `user_id` 当作身份凭证；若旧 Web 调试页仍在 URL/Form 中带 `user_id`，小程序新实现不需要复制该参数。

`/me/profile` 返回 `user_id`、`name`、`company`、`phone`、`is_inner_user`、`user_type`、`source`，部分字段可缺省；不保证有 `user_role`。

## 2. 问答

### 2.1 发送消息

```http
POST /api/v1/chat/stream
Accept: text/event-stream
X-Stream-Protocol: events-v1
```

| JSON 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `message` | string | 是 | 消息文本，1–20000 字符 |
| `thread_id` | string | 否 | 继续会话时传；新会话不传 |
| `intent_hint` | string | 否 | 入口意图，见下表；普通对话不传 |
| `knowledge_type` | string | 否 | `enterprise/demand/solution/achievement/expert` |
| `intent_confirmation` | string | 否 | `confirmed/rejected` |
| `flow_action` | string | 否 | `back/switch/immediate_match/interrupt/next_match_batch` |
| `draft_context` | object | 否 | 当前草稿信息；匹配时可含 `draft_id`、`draft_type`、`fields`、`text` |

`thread_id` 是会话连续性的唯一前端标识：新建会话时不传，收到 `start.thread_id` 后保存并在后续消息中复用。切换身份时不得复用其他身份的本地会话 ID。

```json
{"message":"帮我查找设备质检方案","thread_id":"session-xxx","intent_hint":"supply_demand_match"}
```

| 入口 | `intent_hint` |
|---|---|
| 企业画像 | `enterprise_profile` |
| 需求发现 | `demand_discovery` |
| 供需匹配 | `supply_demand_match` |
| 客户拜访（内部用户） | `customer_visit` |
| 我有需求 | `demand` |
| 我有方案或成果 | `supply_draft`；选定后为 `solution/achievement` |
| 联系客服 | `contact_request` |

### 2.2 SSE 响应

| 事件 | `data` 字段 |
|---|---|
| `start` | `thread_id` |
| `progress` | `text`、`stage`（非固定枚举） |
| `token` | `text`；文件解析可能带 `phase` |
| `done` | `result`：最终响应对象 |
| `error` | `message`，可选 `code/stage` |

最终响应示例：

```json
{
  "thread_id": "session-xxx",
  "status": "SUCCESS",
  "answer": "回答文本",
  "intent": {},
  "draft": null,
  "drafts": [],
  "match_results": [],
  "images": [],
  "ui_blocks": [],
  "actions": []
}
```

`done.result` 为最终结果，HTTP 200 不代表业务成功。断连无终态时，先查询同一会话历史，不自动重复提交。

知识库没有候选，或相关性审核剔除了全部候选时，后端可按当前策略回退到公开联网搜索。联网结果属于公开网页信息，不应伪装成知识库命中；显示后端返回的 `answer` 和来源/状态，不因联网失败而补回已判定无关的候选。

`draft/drafts[]` 为草稿内容；`match_results[]` 为匹配卡片。草稿按 `draft_id` 去重，同名不同 ID 不合并。

新建会话只表示创建新的对话线程，不代表新注册用户，也不保证 OPIEos 的跨会话/用户级长期记忆已被技术隔离。后端会在新会话首轮提示模型优先使用当前会话、不要把长期记忆中的身份或业务资料当作当前用户事实；这是模型提示约束，不是访问控制或硬隔离。前端不得把“新建会话”描述为清除了长期记忆，也不得将旧会话消息拼入新线程。

`ui_blocks[]` 常见 `type`：`answer/draft_card/recommendation_list/human_input/notice`。`human_input.data` 可含 `fields/options/context`；补充信息通过普通 `message` 提交。

### 2.3 操作按钮对应接口

`actions[]` 常见字段：`id/type/label/enabled/message/value/request/draft/draft_context`。`request` 是请求字段对象，不是 URL。

| `action.type` | 接口和参数 |
|---|---|
| `SAVE_DRAFT` | 第 4 节 PATCH 草稿接口；无持久化 ID 时才 POST 新建 |
| `PUBLISH_DRAFT/CONFIRM_DRAFT` | 普通草稿先保存再发布；拜访确认调用第 4.3 节 |
| `EDIT_DRAFT` | 第 4 节 GET 草稿详情 |
| `START_MATCHING` | 聊天接口；使用 `request` 中字段，通常 `intent_hint=supply_demand_match`、`intent_confirmation=confirmed` |
| `IMMEDIATE_MATCH` | 聊天接口；`flow_action=immediate_match`、`intent_confirmation=confirmed`、当前 `draft_context` |
| `MATCH_DRAFT/REMATCH_DRAFT` | 用户确认保存发布后，依次保存、发布，再带当前 `draft_context` 调聊天匹配 |
| `NEXT_MATCH_BATCH` | 聊天接口；`flow_action=next_match_batch`，复用 `thread_id` |
| `BACK_FLOW/SWITCH_FLOW` | 聊天接口；`flow_action=back/switch` |
| `SELECT_UPLOAD_INTENT/SELECT_MATCH_INTENT` | 解析文件接口；`intent_hint=action.value` |
| `SUPPLEMENT_CURRENT_DRAFT/CREATE_NEW_DRAFT` | 解析文件接口；`attachment_mode=supplement/new` |
| `SELECT_SUPPLY_TYPE` | 继续文件或聊天请求；`intent_hint=action.value` |
| `CONTACT_WECOM` | 客服动作，见第 5.4 节 |

普通对话选择动作使用返回的 `request/message/value`；`message` 缺失时才使用 `label`，不可将保存、发布动作仅作为文字消息发送。

### 2.4 匹配结果“换一批”

这不是 `page/offset/cursor` 分页。后端在同一 `thread_id` 保存本次检索条件和已展示结果，前端按当前结果的 `actions[]` 提供的 `NEXT_MATCH_BATCH` 动作继续取下一批。

首次同时命中原文和关联草稿时优先返回原文卡片，详情关联选中的草稿。换批时，已展示文档的解析原文不再作为卡片返回，选中的关联草稿也不重复返回；同一 `source_id` 下其他未展示草稿仍可返回。此规则由后端执行，前端无需新增请求参数，也不限制原有详情查询。

```http
POST /api/v1/chat/stream
Accept: text/event-stream
X-Stream-Protocol: events-v1
Content-Type: application/json
```

```json
{
  "message": "使用当前响应 NEXT_MATCH_BATCH 动作的 message",
  "thread_id": "session-xxx",
  "flow_action": "next_match_batch"
}
```

- `thread_id` 必须使用产生当前匹配结果的会话 ID；不要新建会话，也不要把“换一批”当作新的检索问题提交。
- 请求期间对该会话禁用“换一批”，同一 `thread_id` 同时只发一个续取请求，避免重复点击跳过批次。
- 每批最多返回 3 条。请求成功后读取 SSE `done.result`，用这一批的 `match_results` 替换当前匹配卡片；不要把新旧批次追加成同一组结果。
- 根据最新 `done.result.actions[]` 更新“换一批”按钮。仅当存在 `type=NEXT_MATCH_BATCH` 且 `enabled` 不为 `false` 时显示/启用。
- 若 `done.result.status=NO_EVIDENCE` 或响应中没有可用的 `NEXT_MATCH_BATCH` 动作，停止继续请求并隐藏/禁用按钮；显示返回的 `answer`。网络错误时保留当前结果，不要自动重复提交。

普通列表分页与此不同，见第 5 节和第 6 节。

## 3. 上传文件

### 3.1 接口

| 接口 | 响应 |
|---|---|
| `POST /api/v1/chat/materials/parse/stream` | SSE，最终为 `done.result` |
| `POST /api/v1/chat/materials/parse` | JSON，结构同 `done.result` |

两者均使用 `multipart/form-data`：

| 表单字段 | 必填 | 说明 |
|---|---|---|
| `file` | 是 | 一个 PDF、Office、TXT、图片或音频文件 |
| `thread_id` | 否 | 当前会话 ID |
| `message` | 否 | 文件补充说明 |
| `intent_hint` | 否 | 已确定的入口意图，见 2.1 |
| `knowledge_type` | 否 | 已确定的知识类型 |
| `attachment_mode` | 否 | `new/supplement`，默认 `new` |

普通对话只上传文件且未明确意图时只总结；明确草稿意图后才生成对应草稿。后续“整理草稿”通过聊天接口发送，不重复上传。材料暂存过期返回 410，需要重新上传。

返回常用字段：`status/answer/thread_id/document_id/source_name/draft/drafts`。仅有结构化 `draft/drafts` 才存在草稿；`DRAFT_MULTI_CONFIRM_REQUIRED` 表示待确认拆分或合并，选择作为聊天消息提交。客户拜访不拆分。

### 3.2 文件归属确认

```http
POST /api/v1/chat/materials/prepare
Content-Type: multipart/form-data
```

| 表单字段 | 必填 | 说明 |
|---|---|---|
| `count` | 是 | 固定 `1` |
| `thread_id` | 否 | 当前会话 ID |
| `intent_hint` | 否 | 已明确的入口意图 |

返回 `status/answer/intent/actions`，部分响应含 `thread_id`。

`UPLOAD_INTENT_REQUIRED`：待选择方向；`MATERIAL_ATTACHMENTS_PENDING_CONFIRM`：待选择补充或新建。仅在需要归属确认时调用；普通无意图上传不需要先调用此接口。

## 4. 草稿

### 4.1 接口

| 操作 | 接口 | JSON 参数 | 响应 |
|---|---|---|---|
| 列表 | `GET /api/v1/me/drafts?limit=50` | 无 | 记录数组 |
| 详情 | `GET /api/v1/drafts/{draft_id}` | 无 | 记录对象 |
| 新建 | `POST /api/v1/drafts` | `draft` 必填，`thread_id` 可选 | 记录对象，201 |
| 保存 | `PATCH /api/v1/drafts/{draft_id}` | `draft` 必填，`thread_id/status` 可选 | 更新后的记录 |
| 移除附件 | `POST /api/v1/drafts/{draft_id}/attachments/remove` | `document_id` 或 `storage_key` 至少一个 | 更新后的记录 |
| 发布 | `POST /api/v1/drafts/{draft_id}/publish` | `thread_id/scope_id/replace_existing/idempotency_key` 可选；默认 `scope_id=public`、`replace_existing=true` | `{draft,index_result,idempotency_key,next_step}` |
| 下架 | `POST /api/v1/me/drafts/{draft_id}/unpublish` | `reason_code` 必填，`reason_text` 可选 | 含更新后的 `draft` |
| 重新上架 | `POST /api/v1/me/drafts/{draft_id}/republish` | `{}` | 含更新后的 `draft` |
| 删除 | `DELETE /api/v1/me/drafts/{draft_id}` | 无 | `{draft,status:"DELETED"}` |

发布前先保存；发布接口只允许已确认、待审核或已下架状态。已发布草稿先下架才能删除。移除附件只解除当前稿关联，不删除原文件或其他稿的附件；不能使用第 5 节整文档 DELETE 代替。

上传同名文件会形成新的文档版本，不应让未发布的新版本覆盖仍在使用的已发布版本。只有新版本完成发布后才切换该草稿的附件引用；旧版本仍被其他已发布草稿引用时不得清理。

记录对象示例：

```json
{
  "draft_id": "draft_abc",
  "draft_type": "demand",
  "draft_title": "设备质检需求",
  "status": "CONFIRMED",
  "thread_id": "session-xxx",
  "version": 3,
  "draft": {
    "draft_type": "demand",
    "title": "设备质检需求",
    "fields": {"title":"设备质检需求","contect":"需求描述"},
    "attachments": [{"document_id":"doc-xxx","file_name":"需求.docx","storage_key":"uploads/..."}]
  }
}
```

保存传 `record.draft` 内容，不传整个记录；必须用读取到的最新 `record.version` 做并发校验，请求头传 `If-Match: "3"`（示例版本为 3）。不要把整条记录放进 `draft`。

保存与发布按以下顺序实现：

1. 打开草稿或开始编辑前，读取详情，保存返回的 `record.version`。
2. `PATCH` 请求使用 `If-Match: "{record.version}"`。同一 `draft_id` 一次只允许一个写请求在途；保存或发布请求未完成时禁用重复操作。
3. `PATCH` 成功后，用响应中的完整记录替换该 `draft_id` 对应的本地记录，并更新版本号。后续保存和发布都基于这个最新结果。
4. 有未保存修改时，等待 `PATCH` 成功后再调用 `POST /api/v1/drafts/{draft_id}/publish`。发布接口不接收草稿版本号；`PATCH` 失败时不得继续发布。
5. HTTP `409` 且 `error.message="draft version mismatch"` 表示本次提交的版本已过期：保留用户正在编辑的内容，重新 `GET /api/v1/drafts/{draft_id}`，让用户核对并合并后，再以最新版本重新保存。不要自动重发旧请求体。其他 `409` 按返回的 `error.message` 处理，可能是草稿状态或类型不允许该操作。

若服务端日志只有 `PATCH`、没有随后的 `POST .../publish`，说明流程在保存阶段已失败，发布接口尚未执行。

| 记录状态 | 含义 |
|---|---|
| `CONFIRMED` | 已确认/保存，未发布 |
| `PENDING_REVIEW` | 待审核 |
| `PUBLISHED` | 已发布 |
| `WITHDRAWN` | 已下架 |

多稿逐 ID 更新，不能用单稿的发布结果更新全部卡片。修改已发布稿并保存后回到待发布状态；修改下架稿仍保留下架状态。聊天展示状态 `DRAFT_GENERATED/DRAFT_SAVED` 不等于持久化记录状态。

下架 `reason_code`：`NEEDS_REVISION/OUTDATED/DUPLICATE/PROJECT_ENDED/NO_LONGER_PUBLIC/UPLOAD_ERROR/OTHER`；`OTHER` 必须带非空 `reason_text`。

### 4.2 草稿字段

内容位于 `draft.fields`。若还有 `mysql_fields`，同名编辑字段保持相同值。保留未编辑字段，字段名按原样传递（包括 `contect/analyse_contect`）。

| `draft_type` | 常用字段 |
|---|---|
| `demand` | `title/category/company/contect/analyse_contect/link_name/link_tel/budget_range/demand_cycle` |
| `solution` | `title/pub_dept/product_type/contect/analyse_contect/link_name/link_tel/deliver_cycle/quote_range` |
| `achievement` | `title/category/analyse_contect/tech_maturity/cooperation_mode/company/link_name/link_tel` |
| `customer_visit` | `enterprise_name/enterprise_portrait/potential_demand_list_text/budget_range/expect_cycle/adapt_solution/supplier_match_dim/inner_mark_note` |

`draft.flow_definition.fields[]` 可含 `key/label/required`；`missing_fields` 为待补充字段；`attachments[]` 为当前稿附件。

### 4.3 客户拜访确认

仅内部用户使用；暂存用草稿 PATCH，明确确认记录时调用：

```http
POST /api/v1/business/records/confirm
```

```json
{
  "record_type": "customer_visit",
  "confirmed": true,
  "confirmed_by": "登录返回的 user.user_id",
  "draft_id": "draft_visit",
  "thread_id": "session-xxx",
  "structured_data": {"draft_type":"customer_visit","fields":{"enterprise_name":"示例公司"},"attachments":[]}
}
```

`record_type/confirmed_by` 必填，确认时 `confirmed=true`；`structured_data` 为当前完整草稿。`raw_text/expected_draft_version` 可选。成功返回 201，响应可含 `business_record/visit_record`；拜访不调用公开草稿发布、上下架接口。

### 4.4 用户下架、重新上架与删除

- 下架已发布草稿调用 `POST /api/v1/me/drafts/{draft_id}/unpublish`，必须提交有效 `reason_code`；选 `OTHER` 时 `reason_text` 必填。成功后草稿进入 `WITHDRAWN`，原因保存在草稿状态/审计记录中，管理端可追查。该草稿的向量停止检索；附件版本仅在没有其他已发布草稿引用时一并下架。
- 重新上架调用 `POST /api/v1/me/drafts/{draft_id}/republish`。未编辑的草稿恢复原业务索引及仍有效的附件版本；下架后有过字段编辑的草稿按发布流程同步 MySQL 并重建索引。以接口最终状态为准，失败时保留错误并允许用户重试，不乐观更新为已发布。
- 删除调用 `DELETE /api/v1/me/drafts/{draft_id}` 是逻辑删除：立即从个人中心列表隐藏，响应状态为 `DELETED`；原文和附件不会立即删除。已发布草稿必须先下架。后台仍可查看删除记录；后台管理员彻底删除功能另行保留。
- 当前后端清理循环在服务运行时按北京时间每天 02:00 检查：删除超过 30 天的草稿及关联资源可进入清理；`CONFIRMED`、`PENDING_REVIEW` 未发布草稿超过 30 天未更新时，其附件可进入清理。清理前会检查已发布和共享引用，不应删除仍被其他有效草稿使用的附件；不代表所有状态的未发布草稿都会清理。自2026-11-05起，未保存的临时上传附件有效期为7天，前端应按服务端返回的`expires_at`判断，不硬编码时长。具体以服务是否启用、数据状态和清理结果为准，前端不自行删除对象或索引；附件返回 `retention_status=EXPIRED` 或 `storage_key` 为空时，应隐藏查看/下载入口并显示附件已过期。

## 5. 个人中心

页面包括个人资料、我的文档及附件、草稿、匹配记录、历史会话；内部用户另有客户拜访记录。页面数据可并行加载，单个分区失败不应阻断其他分区；显示具体分区的重试/错误状态。个人资料字段可能缺失，展示前做空值处理。详情、下载和操作都使用当前登录 Token。

当前个人中心列表接口不是页码分页：请求只支持 `limit`，没有 `page/offset/cursor/has_more`。文档和会话响应中的 `total` 仅等于本次返回条数，不是数据库全量数；草稿、匹配记录和拜访记录直接返回数组，没有 `total`。

| 列表接口 | 默认 / 最大 `limit` | 响应和前端处理 |
|---|---:|---|
| `GET /api/v1/me/documents` | 50 / 200 | `{documents,total,user_id}`；文档按更新时间倒序；`total` 等于 `documents.length` |
| `GET /api/v1/me/drafts`、`GET /api/v1/drafts` | 50 / 100 | 草稿数组；按更新时间倒序 |
| `GET /api/v1/me/match-results` | 50 / 200 | 匹配记录数组 |
| `GET /api/v1/me/visit-records` | 50 / 200 | 拜访记录数组 |
| `GET /api/v1/me/conversations` | 50 / 100 | `{sessions,total,user_id}`；会话按更新时间倒序；`total` 等于 `sessions.length` |
| `GET /api/v1/chat/sessions/{thread_id}/messages` | 20 / 20 | 该会话最近最多 20 条消息，按时间正序返回 |

当前接口没有翻页游标；个人中心不能把客户端每页展示数量误作后端分页，也不能仅凭 `total` 宣称是用户全部历史数量。当前 Web 页的列表再按客户端页面切片展示，这不改变服务端返回条数。

前端可以对已取回的数据做本地分页。首次列表请求可省略 `limit` 使用默认值；点“加载更多”时，将 `limit` 调大后重新请求（不超过表中最大值），接口仍从最新记录开始返回，因此用新响应整体替换本地列表，再在客户端切换显示页即可，不要把重叠数据直接追加造成重复。到最大 `limit` 后无法继续向后端取更旧记录。`total` 不能用于计算全量页数。会话消息接口没有“更早消息”参数，重复请求也只会返回最近消息，因此目前不能向后端翻取第 20 条以前的消息；若产品需要真正的历史加载更多，需另行扩展接口契约。

### 5.1 我的资料和附件

| 接口 | 请求参数 | 响应 |
|---|---|---|
| `GET /api/v1/me/documents?limit=50` | Query：`limit` 可选 | `{documents,total,user_id}` |
| `GET /api/v1/me/documents/{document_id}` | Path：`document_id` | `{document,versions}` |
| `GET /api/v1/perception/files/{document_id}/parse-result` | Path：`document_id` | `{raw_text,metadata,...}`；无解析结果为 404 |
| `GET /api/v1/knowledge/documents/{document_id}/file` | Query：`inline` 默认 false | 文件二进制；`inline=true` 仅 PDF 支持内联 |
| `POST /api/v1/me/documents/{document_id}/unpublish` | JSON：`reason_code` 必填、`reason_text` 可选 | 操作结果 |
| `POST /api/v1/me/documents/{document_id}/publish` | JSON：`{}` | 操作结果 |
| `DELETE /api/v1/knowledge/documents/{document_id}` | JSON：`storage_key/knowledge_type` 必填，`scope_id` 默认 public | 删除结果 |

文档项常用 `document_id/source_name/knowledge_type/scope_id/active_version_id/active_version/updated_at`。发布状态取 `active_version.publication_status`，缺失再取 `publication_status/status`。`versions[]` 为版本记录，解析图片清单为 `metadata.images`。

下架原因同 4.1。整文档 DELETE 会删除原文件及相关索引和解析产物，可能影响共用附件；草稿附件移除只能用 4.1 的专用接口。文件下载同样使用 Bearer，URL 的 `user_id` 不提供身份认证。

### 5.2 我的草稿

列表、详情、保存、发布、下架、附件移除和删除均使用第 4 节。详情内容取 `record.draft`，操作返回后按 `draft_id` 替换对应记录。

### 5.3 匹配记录与拜访记录

| 接口 | 请求参数 | 响应 |
|---|---|---|
| `GET /api/v1/me/match-results?limit=50` | Query：`limit` 可选 | 匹配记录数组 |
| `GET /api/v1/me/visit-records?limit=50` | Query：`limit` 可选 | 拜访记录数组 |
| `DELETE /api/v1/me/visit-records/{record_id}` | Path 使用 `business_record_id` 或 `mysql_record_id` | `{record,index_result}` |

匹配记录示例：

```json
[{
  "result_id": "match-xxx",
  "session_id": "session-xxx",
  "query": "匹配问题",
  "draft_id": "draft_abc",
  "created_at": "2026-10-15T02:00:00Z",
  "result": {"answer":"匹配说明","match_results":[],"ui_blocks":[]}
}]
```

匹配卡片取 `record.result.match_results`；缺失时取 `record.result.ui_blocks[].data.items`（`type=recommendation_list`），两者不重复显示。详情接口见第 7 节。

拜访记录字段：`record_id/business_record_id/mysql_record_id/draft_id/thread_id/draft/attachments/match_results`。删除时不使用 `draft_id`；拜访入口仅内部/管理员可见。

## 6. 历史会话

| 接口 | 请求参数 | 响应 |
|---|---|---|
| `GET /api/v1/me/conversations?limit=50` | Query：`limit` 可选 | `{sessions,total,user_id}` |
| `GET /api/v1/chat/sessions/{thread_id}/messages?limit=20` | Query：`limit` 可选 | 最近消息，按时间正序返回 |
| `PATCH /api/v1/chat/sessions/{thread_id}` | JSON：`title` 必填，1–80 字符 | `{session}` |
| `DELETE /api/v1/chat/sessions/{thread_id}` | 无 | `{deleted:true,thread_id}` |

消息示例：

```json
[{
  "message_id": "msg-1",
  "thread_id": "session-xxx",
  "role": "assistant",
  "content": "草稿已生成。",
  "created_at": "2026-10-15T02:00:00Z",
  "response": {"answer":"草稿已生成。","drafts":[],"match_results":[],"images":[],"ui_blocks":[],"actions":[]}
}]
```

消息接口仅返回最近 `limit` 条（默认及最大值均为 20），数组按时间正序排列，便于直接追加渲染；当前不支持 `before/cursor/offset`，不能通过重复请求翻取更早消息。

用户文字取 `content`；助手回答和卡片取 `response`，结构同 `done.result`。历史草稿是快照，编辑前 GET 最新记录。

删除会话还会删除该会话关联且已写入的部分业务记录，须告知用户并确认；不代表清理了全部关联附件和索引。新建会话不调用删除接口。

新建会话应清空当前页面消息、放弃当前 `thread_id`，并在下一条消息请求中省略 `thread_id`；不调用会话删除 API，也不应删除用户其他会话。浏览器端当前以用户 ID 隔离本地保存的活动会话 ID；小程序请使用同等的按登录身份隔离方式。

## 7. 匹配详情与图片

### 7.1 结果详情

```http
POST /api/v1/knowledge/chunk-detail
```

| JSON 字段 | 必填 | 说明 |
|---|---|---|
| `document_id/mysql_id/source_id` | 至少一个 | 从当前匹配卡片取值 |
| `chunk_role` | 是 | 原样传当前卡片值 |
| `chunk_index` | 是 | 非负整数 |
| `knowledge_type` | 否 | `enterprise/demand/solution/achievement/expert` |
| `include_summary` | 否 | 默认 `true`；卡片仅补取 chunk 图片信息时传 `false`，跳过摘要生成 |

返回 `text/draft/draft_chunks/source_chunks/cleaned_source_text/formatted_text/image_urls/documents`，字段按实际结果出现。404 表示无详情。`documents[].can_download` 为下载标记。

图片清单暂时无法读取时，文字仍返回，`image_error_code="IMAGE_MANIFEST_UNAVAILABLE"`、`image_error` 为可展示提示；相关图片暂不展示，不表示已删除，不清空本地或服务端保存的图片引用。稍后重新打开详情可再请求。

每批匹配最多 3 条；卡片常用 `id/title/summary/details/score/knowledge_type/document_id/mysql_id/source_id/chunk_role/chunk_index/image_ids/image_urls/source`。

同一来源同时命中多个草稿时，只保留本次检索得分最高的草稿；同时命中原文时优先展示原文，并通过 `matched_draft_record_id` 保留选中的草稿索引记录 ID。详情请求原样传回该可选字段，`draft/draft_chunks` 只返回选中的关联草稿。原文的 `mysql_id` 可以为空，不能用文档 ID 随意关联其他来源的草稿。

小程序不必增加参数。未传 `matched_draft_record_id` 时，单草稿直接返回；多个关联草稿由后端以当前命中原文 chunk 为查询，通过现有重排服务选一条，返回其完整草稿分块。不调用 GPT、不依赖“最近一次会话”。该方式选择的是与原文最相关的草稿，不保证与用户原始问题的最高分选择相同。无法选出时不随意选第一条：`draft` 为空、`draft_chunks=[]`，原文详情照常返回，`draft_selection_error` 说明原因，后台记录告警。若已有调用方传入该可选字段，则直接使用本次检索选中的草稿，不再重排。

只有一个关联草稿时直接返回，不额外评分或调用模型。同一文档、同版本、同位置且内容一致的原文块即使存在多个来源引用，也只显示一次。

### 7.2 图片地址

```http
GET /api/v1/perception/images/{document_id}/{image_id}
```

返回图片二进制；404 表示图片不存在。标准图片地址可能没有扩展名。

| 返回字段 / 内容 | 含义 |
|---|---|
| 当前卡片 `image_urls[]` | 本条匹配图片 URL |
| 当前卡片 `document_id + image_ids[]` | 对应上述标准图片接口；`document_id` 也可能在 `source.document_id` |
| `images[]` / `metadata.images[]` 的 `url/image_url` | 可访问图片地址；清单另含 `image_id/document_id/relative_path/source_locator` 等关联字段 |
| `![说明](URL)`、`<img src="URL">` | 正文中的图片引用 |
| `方案封面图：/api/v1/perception/images/...` | 裸图片地址，同样表示图片 |
| `http://...` / `https://...` | 完整 URL，保留原地址 |
| `/api/v1/perception/images/...`、`/api/v1/perception/assets/...` | 服务相对地址，前缀为接口地址 |
| `images/xxx.jpg`、`/images/xxx.jpg` | 解析关联路径，不是可直接请求的公开地址，需对应图片清单中的 URL |

卡片只关联当前命中项的图片；详情分块通过 `document_id + chunk_role + chunk_index` 对应。不得将整轮图片或相邻分块图片放到每张卡片。附件也只按当前项的 `document_id/source_id` 关联。匹配卡片最多展示 3 张图；查看详情时按命中的分块请求并展示详情返回的完整图片列表，不要截断或改写服务端保存的图片引用。

封面图和解析原文图片的受管 URL 统一为 `/api/v1/perception/images/{document_id}/{image_id}`。前端按服务端返回的 `url/image_url/image_urls` 渲染，只在相对地址前拼当前环境的 API 根地址；不要自行拼 MinIO URL、旧域名或 `images/...` 解析路径。外部网页图片 URL 原样处理。

## 8. 错误响应

```json
{"error":{"code":"CONFLICT","message":"提示内容","details":null},"trace_id":"..."}
```

| HTTP 状态 | 含义 |
|---|---|
| 401 | 未登录或 Token 过期 |
| 403 | 无权操作 |
| 404 | 记录、文件或解析结果不存在 |
| 409 | 状态不允许或版本冲突，按 `error.message` 区分 |
| 410 | 资料过期，需要重新上传 |
| 422 | 参数无效，详情位于 `error.details` |
| 429 | 请求过频，等待 `Retry-After` 指定秒数 |
| 5xx | 服务处理失败 |

SSE 失败还可能通过 `error` 事件或 `done.result.status` 返回；不能仅按 HTTP 状态判断成功。
