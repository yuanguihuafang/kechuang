# 科创 Backend 全模块功能与冗余审计计划

## 目标

逐模块核对科创 Backend 的职责、入口、调用关系和已有文档；定位当前仍存在的确定性问题与可证明的冗余，只做最小清理，并同步项目自有文档与总索引。

## 范围与保护边界

- 主范围：`backend/admin`、`agents`、`api`、`core`、`evaluation`、`migrations`、`runtime`、`services`；`backend/tests` 仅作行为和契约证据，不在本轮运行测试。
- OPIE/DeerFlow 仅作为外部依赖只读核对调用契约；不修改 `OPIEos` 目录中的源码、Agent、Skill 或配置。
- 前端是测试界面，本轮不重构；仅在后端接口/行为文档需要同步时检查其契约。
- 排除 `bakup` 快照、`.venv`、运行数据、环境文件、上传资料及生成文件。
- 工作区现有未提交改动视为用户内容；不重置、不批量格式化、不覆盖无关修改、不提交。OPIEos 下已有改动无论是否相关均不触碰。

## 审计与实施顺序

1. **基线盘点**：以本索引和既有架构/验收文档为准，记录模块入口、文档范围、当前未提交文件及不验证事项。
2. **分域只读审查**：分别审查 API/管理入口、Agent/应用服务与 Core/运行时；每项问题须附文件位置、调用证据和影响说明。
3. **确认冗余**：删除候选须满足无静态调用且无路由注册、动态发现、反射、插件、Agent/Skill、脚本或外部契约入口；无法排除的只记录，不删除。
4. **小步清理**：只处理证据充分、与现有用户改动不冲突的项目；不顺带重构、不增加兼容或兜底路径。
5. **文档同步**：修正与当前实现不一致的项目自有文档，补全各模块职责/入口说明，更新 `docs/Agent.md` 索引；保留明确标注为历史的验收记录。

## 验收标准

- 各后端模块的职责和主要入口有明确说明，关键 API、权限、持久化、检索、草稿、上传、MCP/DeerFlow 边界与当前源码一致。
- 每项删除均有调用关系证据；不确定项留存并注明原因。
- 只修改必要源码与项目自有文档，已有未提交内容完整保留。
- 按用户此前要求，本轮不运行测试；完成后仅报告静态审查范围、源码/文档变更和未验证事项，测试由用户执行。

## 已知风险

- 当前工作区已有多处 Backend、OPIEos 定制文件、Agent/Skill、备份和文档未提交变更，需逐文件避让或在重叠时先核对差异。
- 静态无引用无法单独证明代码不可达；所有动态入口都需要额外核对。
- 历史文档中的测试数字和部署状态是历史证据，不得改写成当前运行状态。

## 审计结论（2026-09-28）

### 已清理

- 删除被前置 `/{record_id}` 路由遮蔽、仓库内无调用方的旧知识更新详情路由。
- 删除无读取点的四项旧 Agent 执行参数；当前会话执行由 DeerFlow Gateway 负责。
- 删除 MinerU 自动切换到另一解析器的 runner；按配置选择 HTTP 或本地执行，失败明确返回。
- 删除材料字段提取在模型不可用、调用失败或返回空内容时静默退回原文的行为；错误显式上抛。
- 任务状态统计直接调用 `TaskStore.count_by_status()` 契约，不再通过两次受 500 条上限约束的列表扫描兼容旧替身。
- 修正 Backend Agent、Prompt、Observability README 的实际目录说明，并校正文档索引、迁移状态、Skill 部署目录与快速入口现状。
- 未删除任何整个 Backend 模块。测试与历史验收记录保留，未运行测试。

### 保留项与原因

- `preferred_parser` 在当前解析分派中未使用，但测试及配置仍引用；本轮不改变解析器公共构造参数，避免扩大解析路由改动面。后续若决定移除，应一并核对配置调用方与对应解析路由用例。
- `backend/admin/api/v1/schemas.py` 是兼容导出层，但无法从仓库静态调用证明没有外部 Python 导入方，故保留。
- 数据库迁移中的历史版本和潜在破坏性降级未修改；未连接数据库核验部署版本或数据状态。
- `register_translator.py` 及 OPIE/DeerFlow 文件未修改；部署脚本与运行数据的凭据/权限需另行审查，本文不记录凭据值。
- Agent/Skill 动态发现、插件入口、测试替身和 `bakup` 快照不作为静态无引用删除依据。

### 尚未解决的高风险问题

- 记忆 API（`backend/api/v1/memory/routes.py`）使用请求提供的用户标识，未统一经过认证身份校验；清理接口允许缺省用户范围时存在全局影响风险。
- 用户身份查询路由（`backend/api/v1/identity/routes.py`）可按路径中的任意用户 ID 查询资料，未见独立认证/授权约束。
- 草稿管理路由（`backend/api/v1/drafts/routes.py`）的管理员下架入口位于业务路由内，当前 `admin=True`/管理员角色由路由自身赋值，未绑定可信管理员身份。
- 快速入口的选择卡直返仍缺少 Backend 确定性分支；当前代码会进入 DeerFlow，历史验收记录不代表现状。
- 管理服务与 Agent/API 私有 helper、运行时配置层之间仍有跨层依赖；拜访记录查询仍聚合多个 store 并扫描较大草稿范围。需要独立设计与验证，不在本轮顺带重构。
- 服务器网络、容器挂载、DeerFlow Gateway 鉴权、远程 MCP 回调及数据库迁移状态均未在线核验；不得据此宣称服务器已验收。

### 变更边界

- OPIEos 源码、Agent、Skill、配置：本轮未修改。工作区已有 OPIEos、bakup、测试前端及 Backend 文件的用户改动保持原样。
- 本轮不提交代码、不运行测试、不启动服务、不访问数据库或服务器。
- 静态验证：Backend `ruff check . --select E9,F` 通过；README 与 `docs/**/*.md` 相对文件链接检查通过；本轮目标文件 `git diff --check` 无空白错误。以上不等同于运行测试或服务器验收。
