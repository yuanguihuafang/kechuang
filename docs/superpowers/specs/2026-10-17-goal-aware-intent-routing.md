# 目标导向的问答意图分流

## 目标

让科创助手依据用户完整表达和当前会话理解最终目标，再选择联网搜索、知识库检索、匹配或草稿等工具；不因单个关键词就机械触发工具。只在关键歧义会改变操作或结果时追问。

## 分流规则

1. 先检查可信身份及权限；身份不能从用户自述推断。
2. 结合本轮完整消息和当前会话上下文识别目标，区分目标、对象、资料来源和希望得到的结果。目标优先于局部关键词。
3. 用户明确选择且与表达目标一致的快速入口，作为强意图提示，直接走该入口对应流程和工具，不重复询问。
4. 快速入口与本轮目标明显不一致时，不强行执行入口流程；用一句话复述冲突并询问用户要继续入口目标还是改按本轮目标处理。
5. 未选择快速入口时，目标和操作足够明确则执行；资料来源等关键选择未明确且会显著改变结果时，先询问。不得为低影响细节增加确认步骤。
6. 意图追问使用普通会话文本；用户答复后从已保存的上下文继续，不要求重复描述。没有确认前不调用受该选择影响的检索/匹配/写入工具。
7. 联网、知识库、匹配、草稿均是实现目标的工具，不是由关键词自动决定的独立目标。保留现有身份权限、草稿版本/保存发布及匹配规则。

## 示例与验收

- 自由输入“帮我查河北利仕化学，我一会要去走访挖掘场景需求”：理解为拜访前准备，不直接展示企业库匹配卡片；确认联网、内部知识库或两者后，再按选择生成简明需求方向与走访问题。该拜访准备仅限内部用户。
- 选择“企业画像”并输入“河北利仕化学”：入口与目标一致，直接检索企业资料，不再询问资料来源。
- 选择“企业画像”但明确要求“帮我新建一份技术方案草稿”：识别入口与目标不一致，先确认，不调用画像检索或草稿写入。
- 自由输入“查询河北利仕化学的联系方式”：目标清楚，直接执行合适的企业资料检索，不额外追问。
- 用户明确说“检索内部知识库中的相关需求”：直接调用对应知识库检索；不转成联网搜索。
- 外部用户提出客户拜访记录或拜访准备：不得调用仅限内部的拜访能力；仍按已有权限规则答复或引导。

## 实施边界与验证

- 优先调整现有 Agent 规则和工具描述，不新增单独的意图识别模型调用，不要求前端新增交互协议。
- 增补上述分流场景的定向回归检查；验证意图、工具选择、追问状态和权限边界。无需全量测试与本目标无关的模块。
- 本稿只定义预期行为；不包含实现、部署、服务端配置修改或线上验证。

## 检索相关性与联网回退（本次扩展）

### 范围

统一适用于所有检索类结果：知识检索、企业/专家资料、需求发现、供需匹配及换一批。不能只针对“企业拜访”示例增加特例。

### 相关性判断

- 使用用户完整问题、会话目标及检索候选内容，由 LLM 在生成匹配卡片前判断候选是否能回答当前目标；不因检索返回了候选就强制展示，也不保证凑满 3 条。
- 宽泛类别、方向或“相关类型/可参考”的查询使用宽松判断：主题相近且有参考价值的候选可以展示，并说明它是相关参考而非精确命中。
- 具体对象或事实查询（例如指定公司、指定案例或明确产品/需求）使用严格判断：候选必须确实对应对象/问题；仅关键词相似不算相关。没有相关候选时返回空的知识库匹配卡片集。
- 不相关候选不得作为知识库结果返回。已有匹配、草稿、来源、权限和换批身份规则继续生效。
- 换一批继续使用首轮保存的完整用户目标与联网回退判断；不因换批而扩大知识库范围。

### 联网回退

- 当确实没有相关知识库候选时，由 Agent 根据用户完整目标、上下文和明确来源限制决定是否直接尝试公开联网搜索；不因资料来自草稿、附件或内部记录就一概禁止，也不为“是否联网”增加追问。用户明确限定“只查内部知识库/不要联网”或当前身份/权限不允许时不得联网。
- 联网词（`query`）应围绕用户目标提炼，必要时可参考草稿或附件中的主题；不得把候选正文或整段草稿/附件原文直接转发给联网服务。相关性判定模型不生成联网词。
- 联网结果以普通文字和来源链接提供，不能伪装成内部知识库匹配卡片或供需匹配结果。供需匹配找不到内部候选时，可以补充公开信息，但必须明确没有内部匹配。
- 联网服务失败时如实说明未能获取公开结果，不得恢复展示已判定无关的知识库候选，也不得编造结果。

### 成本与验证

- 相关性判定按一次检索批次合并候选进行，不逐条请求模型；无候选时跳过判定，按 Agent 对完整目标作出的联网回退判断处理。检索工具传递完整用户目标和明确来源限制。
- 该行为会在有候选的检索批次增加一次 LLM 判定调用；通过测试确认广义查询保留相近候选、具体查询拒绝无关候选、无命中按模型判断联网回退、显式内部限定不联网、权限及供需匹配边界不变。
- 不改前端协议；实现时需确认现有共享结果出口能在卡片组装前过滤，并能将联网回退结果作为文字返回。
