# 知识库简答、需求发现与换批修订

## 目标

- 所有知识库检索统一在重排后最多返回前三个不同对象；匹配卡片承载完整信息，回答只用中文做不超过 200 字的简短总结，不输出表格或逐条复述卡片，也不以截断代替模型总结。
- “需求发现”检索需求库；与主题相关的企业画像/拜访记录可作为证据卡片，不创建需求、方案、成果或拜访草稿，除非用户明确要求创建/保存。
- “换一批”沿用查询和方向，以服务端已展示对象身份排除之前结果；不足三条时如实返回，不补回旧对象。
- 匹配结果卡片标题行展示“匹配结果 · N 条”，不另设左侧计数列。
- 匹配结果中的“立即补充”必须携带当前主题进入对应草稿流程，并返回可编辑草稿卡片。
- 对 OPIE Gateway 已有模型/工具事件补齐可观测阶段耗时；不改 DeerFlow 核心，不启动或重启服务。

## 边界与验收

- 不改变公开聊天 API 参数；MCP 工具只暴露本任务所需的检索范围，重排开启且最多三条。
- 检索摘要的 200 字上限由 Agent/Skill 提示约束；不得程序硬截断模型输出。
- 检索方向、用户明确入口和工具权限以现有请求上下文为准；只有明确用户指令才能进入草稿创建流程。
- 用回归测试验证检索上限、排重身份、简短中文输出策略、需求发现不建草稿、补充草稿上下文及阶段计时；完成后检查前端构建。在线服务由用户启动，未做真实模型端到端验证时明确标注。

- 已完成 Backend 检索结果上限、重排候选扩充、会话级换批排重、需求发现路由、工具前过程消息抑制、补充草稿上下文和卡片布局修改；OPIE Agent/Skills 已补充简体中文短总结规则，Gateway 已增加模型与工具阶段耗时日志。
