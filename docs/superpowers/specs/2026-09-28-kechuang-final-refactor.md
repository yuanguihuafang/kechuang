# 科创 Agent 与后端完整重构验收

## 目标与边界

以 DeerFlow `kechuang` Agent 作为唯一业务意图识别和问答编排入口。科创后端保留身份、权限、持久化、字段合同、文档处理、检索重排、发布和管理操作；不保留旧主 Agent 回退或额外的语义分类模型。所有修改保留用户现有数据及无关工作区变更，不提交代码。

## 修改前发现

- SOUL 允许普通对话及一般外部公开信息，联网 Skill 同样缺少业务范围限制，因此天气、餐饮会被回答甚至编造。
- SOUL 中需求发现入口仍写企业/客户资料分析，与需求库检索 Skill 存在冲突；方案/成果输出规范仍要求正文复述字段；字段提取 Skill 仍把完整 MySQL 合同混入智能问答。
- `runtime/bootstrap.py` 同时装配 DeerFlow 和旧 Supervisor；聊天、材料、会话存储及管理恢复耦合旧主 Agent。需逐个迁移被使用的确定性能力，再删除无调用的旧编排代码。
- 日志格式将全部 INFO 染绿；普通请求、SDK 请求和关键业务阶段难以区分。
- 系统 Python 缺 MCP，Conda `D:\Anaconda\envs\py311\python.exe` 已具备 MCP/pytest；使用项目已有环境验证。

## 运行约束

遵守用户自行启动后端的要求，检查和测试不自动启动业务服务。关机属于用户已授权的最终动作，但必须在所有工作完成后执行；不使用强制关闭应用参数。

## 验收记录

### 第一阶段：入口收敛

聊天及聊天材料入口只允许调用 DeerFlow；未装配时在身份校验后返回 503，且在上传/解析前阻止无效处理，不再自动运行旧 Supervisor。先删除两处回退和只被回退调用的 SSE 代码，再迁出会话状态，最后清除旧 Agent 模块。管理台解析/提取不受聊天运行时是否就绪影响。

会话持久化迁至 `services/application/conversation_state.py`：只合并上下文、活动草稿和匹配批次，不创建模型、意图分类器或 LangGraph。运行时直接装配该服务与 PostgreSQL 会话仓储。旧 `supervisor_compensation` 属于移除的编排协议，不再重放旧模型执行图；管理台保留文档生命周期补偿和现有文件任务恢复入口，遇不支持的旧任务明确报错，不静默转译或删除历史记录。

性能检查确认 OPIE 的 `/runs/stream` 有 `require_existing=True` 权限检查；不能仅因请求体有 `if_not_exists=create` 就删除创建 thread 请求。此处不进行未经验证的省请求改动。

阶段验证：入口/会话服务迁移后后端全量 572 项通过。旧 Agent 的共享合同仍待迁出，不能据此认定整体重构完成。

### 第二阶段：重排与草稿边界

内部画像从 MySQL 读取权限内候选，再使用现有重排服务返回前三条，不能先按 SQL 分数截成三条再交给模型。候选数量沿用检索召回配置；完整字段留在卡片详情。请求启用重排时，重排未配置、超时或返回无效结果均明确失败，不回填未重排结果。空候选正常返回空集合，不额外请求模型。

拜访草稿与另外三类草稿统一使用 draft_contracts 的字段、长度和必填规则，以及版本校验的创建/读取/编辑接口；保存确认仍走私有业务记录及索引，不能以“同会话已有不同内容”的幂等冲突禁止合法编辑。删除、下架等未闭环能力不得由 Skill 宣称。

### 第三阶段：共享合同迁出旧 Agent

将聊天请求/响应、流程元数据、会话状态定义移到 `core/contracts`；确定性的草稿装配、卡片响应和查询前置校验移到 `services/application`。所有调用方直接引用新位置，不留 re-export 兼容层。先保证实际运行路径不再 import 旧主 Agent，再删除旧执行图及专属测试；数据库历史运行记录不删除。

引用核查：旧 `agents/intent_agent`、`agents/supervisor_agent`、`agents/reasoning_agent`、`runtime/agent_registry` 及对应 intent/planning/reasoning 提示词仅在旧执行图和其专属测试间调用。`chat_response.annotate_evidence_sources` 本身无调用，连同旧引用编号转换一并移除，不再迁移兼容代码。保留混合测试文件中实际会话状态、草稿、检索排序、权限与网页结果的测试；移除只验证已退役执行图的用例。新增架构检查防止已退役模块重新进入生产代码。

旧执行图及专属提示词/测试共移除 66 个文件；共享行为测试继续保留。清理后完整后端测试 473 项通过（1 条既有弃用警告）。测试数量下降来自退役旧执行图，不是跳过失败用例。

### 第四阶段：使用原生共享 Skill 目录

13 个科创 Skill 从 `OPIEos-main/skills/custom/kc-*` 迁至 `skills/public/kc-*`，由 Agent 的名称白名单按需加载。原生 public 类别不会因为用户创建个人 Custom Skill 而整批消失；不修改 DeerFlow 存储器或新增兼容层。个人同名 Skill 的原生覆盖行为保留，部署时必须检查并清理经确认已过时的同名覆盖，而非无差别删除用户目录。`/api/skills` 可查看共享技能，`/api/skills/custom` 只显示个人可编辑技能。

### 第五阶段：HTTP 与 MCP 使用相同的拜访权限边界

草稿 HTTP 路由也是 MCP 调用的实际写入口。内部拜访草稿的创建、读取、编辑和列表过滤在该边界验证当前身份；不能只在模型工具上检查权限。编辑不得改变既有草稿类型；拜访不进入公开发布/下架/重新上架链路，也不通过通用状态转换冒充发布。未闭环的拜访删除明确拒绝，保留私有记录及索引，避免只删卡片留下可检索数据。

### 第六阶段：Skill、模型边界与最终回归

逐一对照全部 13 个 Skill 与实际 MCP schema：文档 Skill 只承诺已暴露的列表、详情、解析结果和重解析，不承诺管理台原文编辑、封面更换或重建索引；草稿 Skill 区分保存版本与发布同步；匹配结果仅进入卡片和会话，明确要求写回时才更新合同允许的业务字段。字段提取的新增场景合入 `contect` 并保留原事实，不提交 full 模式的 `application` 字段。六份引用规则修改分别完成修改前边界核查和修改后场景核验。

移除无调用的旧 Supervisor 工具名枚举、参数/输出模型、输出校验器和执行适配方法；仍在使用的文件工作流、检索、联网搜索、执行服务和生命周期接口保留。没有删除用户数据、附件、历史记录或环境，也没有提交代码。
