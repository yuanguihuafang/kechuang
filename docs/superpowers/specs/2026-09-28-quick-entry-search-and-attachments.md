# 快速入口、检索与附件行为修订

## 目标

- 首轮业务请求缺少具体主题、问题或应用场景时，由 OPIE Agent/LLM 用简体中文自然追问必要信息；不检索知识库/联网、不生成草稿。首页三条问题只是参考示例，不是穷举，也不要求固定回复。
- “需求发现”给出具体主题后直接检索需求库，不自动建草稿；具体方向由用户显式选择时优先于模型判断。
- 所有“换一批”基于已展示的业务记录 ID 做服务端排除；检索工具仍请求 `top_k=3`，检索层按排除 ID 扩大候选召回，旧结果不得回填。
- 换批不写会话级临时标记；只有 Agent/LLM 在本次检索工具调用中判定为换批，MCP 才读取持久化的已展示记录并排除。失败/断流无需清理临时标记，新查询不会继承换批条件。
- 知识库回答保持中文简短摘要，详情留在卡片；联网搜索分条总结，不输出 URL，也不受知识库 200 字摘要规则约束。
- 附件随草稿保存并在用户草稿和管理台详情中展示；用户可下载、删除，权限和存储生命周期由后端校验。

## 边界

- 外部人员首页恢复截图所示布局：“快速开始”只显示三张独立流程卡——“我有需求”（`demand`）、“我有方案 & 成果”（`supply_draft`）、“供需匹配”（`supply_demand_match`）；下方单独显示“也可以直接提问”示例区。需求入口继续展示可选需求类型卡，允许跳过后直接描述/上传；方案/成果入口继续先选择类型；供需匹配未确定方向时继续显示两个可点选方向。所有内部人员快速入口维持原映射和流程。人工客服不是首页快速入口卡。
- 显式快速入口且没有正文/附件时保留固定首步：`demand` 返回可跳过的需求类型卡，`supply_draft` 返回方案/成果类型卡，`supply_demand_match` 返回供需方向选项；后端直接返回，不调用 Agent。内部四个入口（企业画像、需求发现、供需匹配、客户拜访）同样由 Backend 直接返回固定首轮引导/方向选项。首页提问示例和普通自由输入不带快速入口标记，仍由 Agent 处理。
- 首页三条固定问题原文保持为“我有创新需求，帮我匹配专家或成果”“我有技术成果，帮我寻找潜在客户”“我有智能化升级需求，帮我推荐方案商”；它们仅作为普通用户消息发送，不附带快速入口、意图或方向参数。
- 对所有首轮业务消息，若没有足以开始检索/匹配的具体主题、问题或场景，Agent 参考对应示例自然追问，不限于首页三条问题；不要求逐字复述。内外部用户的首轮引导规则一致，身份只影响可用工具和数据权限，不改变信息不足时先追问的行为。用户已给出具体主题或有效材料时正常由 Agent 判断流程，不机械追问。
- 宽泛首轮引导必须落到业务方向对应的具体信息：创新需求问研发难题/技术方向并举产品改良、工艺优化、新材料等例子；技术成果问成果内容、解决的行业问题及适用企业/场景；智能化升级问行业、改造环节并举质检/产线数字化/仓储等例子，可询问大致预算。明确告知可文字描述或上传资料，并说明后续匹配目标。不能只说“请描述具体需求/提供关键词”等泛化句；三类话术是参考，不要求逐字复现，也不限于首页文案。
- 不启动或重启 Backend / OPIE，不改用户运行时数据，不做兼容/回退流程。
- 不为首页示例增加专用请求参数或固定答复分支；只有确需传递检索排除 ID 时才扩展内部请求上下文。
- 前端是测试界面；业务意图、检索排除、草稿附件所有权与读写规则以 Backend/OPIE Skills 为准。

## 验收

1. 外部首页快速卡片只有“我有需求 / 我有方案 & 成果 / 供需匹配”三张，分别沿用 `demand / supply_draft / supply_demand_match` 原流程；需求类型可选、不选仍可描述或上传，方案/成果先选类型，供需匹配显示方向选择。内部四个快速入口在无内容的首轮固定返回各自引导，其中供需匹配显示方向选择；有内容/附件的入口请求按原 Agent 流程执行。下方三个固定问题原文不变，仍作为普通消息提交。“也可以直接提问”与快速入口区域分离。内外部普通消息使用相同的首轮引导规则：业务信息不足时 Agent 参考相应中文示例自然引导补充信息，不要求逐字一致，不搜索知识库/联网、不创建草稿，聊天气泡中不出现“请补充信息”卡片；内部工具和数据权限仍由 Backend 校验。引导必须具体到创新需求、技术成果、智能化升级各自的信息要点，并包含可文字输入/上传资料及后续匹配目标；不得只用泛化追问。其他同类宽泛首轮请求也遵循对应方向的引导；信息充分时正常执行。
2. 普通自由对话未选择入口时仍经过大模型；用户选择供需方向后该方向覆盖 LLM 分类。
3. 需求发现有主题直查需求库，无主题只在气泡中追问；不调用草稿创建工具。
4. 换批排除前批业务记录，排重发生在最终 top-3 之前；普通检索与需求发现覆盖，重复 ID 不回填。自然语言表达由意图识别触发；请求成功、报错、断流/取消后临时换批状态均清理，后续新查询不受污染。
5. 联网搜索正文按条目陈述，正文不出现 URL，不使用 200 字限制；检索卡片可保留来源元数据。
6. 草稿保存后附件与草稿关联，用户端可见/下载/删除；管理台草稿详情显示附件；跨用户访问被拒绝。
7. 对应 Backend/OPIE/frontend 定向测试通过；不声称在线模型、对象存储或重启后的端到端已验证。
8. DeerFlow runner 未就绪时问答接口返回 HTTP 503；会话服务未就绪时也应明确返回 HTTP 503，不因尝试读取会话存储而抛出未处理异常。

## 2026-10-09：内部快速入口首轮固定回复

- 内部四个快速入口仅在入口意图已确认、消息仍是入口初始文案、且没有草稿上下文或材料上传时，由 Backend 直接返回固定回复，不调用 Agent。
- 企业画像提示补充企业名称；需求发现提示补充客户/行业/主题；供需匹配继续返回两个方向选项；客户拜访提示描述或上传拜访内容。
- 普通自由输入、用户已提供主题、已有草稿或携带材料时保持原 Agent 流程；权限校验和工具调用不变。
- 固定首轮回复（内部和外部入口一致）在会话状态中暂存入口消息及助手固定回复；下一次 Agent 调用按 `user → assistant → 当前 user` 顺序注入 DeerFlow 线程。业务成功后清除；首次失败保留并允许下一轮重试一次，第二次失败后清除；明确取消/切换意图或超过 30 分钟未使用也清除。只传递这一组入口问答，不把应用会话的完整历史重复注入；没有待注入状态的普通对话请求不变。

## 本次处理范围（2026-09-29）

- 本轮只统一 Agent/Skill 中的信息不足首轮引导，不为首页示例增加专用参数、固定答复或 Backend 快速返回分支；具体主题或有效材料仍由 Agent 正常判断并执行检索/匹配。
- 本轮暂不处理 MCP 草稿创建错误；不改 OPIEos 源码，也不运行测试，留待用户自行验证。
