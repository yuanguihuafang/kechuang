# 上传流程语言、草稿字段与错误阶段修复

## 目标

修复上传材料解析后的用户可见行为：科创 Agent 面向用户统一使用简体中文；材料中有依据的草稿字段需同时进入结构化草稿卡片；解析完成后发生的智能体/检索/草稿处理错误不能再伪装成文件解析失败。验证 PPTX 和图片在当前源码中路由到 PaddleOCR，并让本机 Backend 加载这些改动。

## 快速入口约束

- 用户明确选择快速入口后，该 `intent_hint` 是当前处理流程；上传附件只提供业务内容，不能触发模型把“客户拜访”改判为技术方案/科研成果等其他类型。
- 只有用户明确要求切换意图时才切换；否则继续当前入口流程，不向用户要求重选类型。没有明确入口选择时，保留原有意图识别流程。
- 已选快速入口是 Agent 的权威流程约束：只有用户明确提出切换时才改道；附件只能提供业务事实，不能触发重新分类。上传的动态输入只传递本轮已选入口，通用规则写在 Agent SOUL 和材料解析 Skill。
- 所有 DeerFlow 用户可见回复默认简体中文，只有用户明确要求其他语言时才切换；该规则归 Agent SOUL/业务 Skill，不在 Backend 再复制一份提示词。

## 已确认现状

- `backend/agents/perception_agent/application/field_extraction.py` 的 `draft_only` 路径只在字段已预先存在于 `result["fields"]` 时，才把新提取值同步到卡片字段；新字段可能只进入 `mysql_fields`。
- 科创 Agent 的 `SOUL.md` 约束了业务答复形式，但没有明确面向用户的默认输出语言。
- `SupervisorDebug.jsx` 的上传异常分支对所有错误统一添加“文件解析失败”前缀。
- 当前源码和定向测试把 PPTX/图片路由至 `PaddleOCRDocumentParser`；用户提供的历史运行日志显示调用了 `http://27.223.9.106:9030/file_parse`（MinerU），但日志发生在当前后端代码修改之前，不能代表重启后的路由。
- 已存文件解析曾用请求文件名校验扩展名、却将 MinIO 返回的临时文件名交给解析器，两个名字不同时会选择错误的解析器；现在解析前统一临时文件名与已校验的请求名。
- 提供的日志截止于知识库重排完成，未包含最终 OPIEos 流终止事件或上传端异常尾部；不得据此虚构后续失败原因。

## 实施约束

- 只提取材料、当前对话或登记资料中有证据支持的字段；无依据的值保持为空，不猜测、不伪造。
- `draft_only` 下提取到的合法草稿字段必须进入 `fields` 和 `mysql_fields`，并遵守当前类型的 `DRAFT_FIELDS` 约束。
- 不改变请求参数；SSE 错误事件只增加可选阶段标识。解析完成后的失败说明“解析已完成、后续处理失败”，解析阶段错误仍说明文件解析失败。
- 不加入旧解析器或旧 Agent 回退，不改 DeerFlow 核心，不修改 `.env.local`。
- 仅当识别出运行 PID 和启动方式后，才重启这次工作涉及的本地后端；不停止其他服务。

## 验收

1. 回归测试证明 `draft_only` 的新抽取值同步到可展示的草稿 `fields`，且越类型字段不会写入。
2. SSE 回归测试区分解析阶段错误与解析成功后的处理错误；测试界面显示相符的错误标题。
3. Agent 配置规定默认简体中文，除非用户明确要求其他语言。
4. DeerFlow 上传回归测试证明已选 `customer_visit` 被写入 Agent 用户消息和确认元数据，提示允许用户明确切换、但附件本身不能触发重新分类；无已选流程时仍可识别意图。
5. PaddleOCR 定向测试通过；解析日志记录实际解析器名称。重启后验证 Backend 健康检查；自动测试不重放用户文件或调用外部 OCR 服务。
6. 运行相关后端测试、前端测试/构建；说明未覆盖的真实外部服务验证。

## 本轮核验结果

- 附件日志显示 MinerU 在 20:50 成功解析，后续检索重排在 20:52 成功；日志没有包含最终 SSE 错误尾部。前端“文件解析失败”是因为解析后阶段错误也被归为解析错误，现通过 SSE `stage` 区分。
- 请求文件名与存储临时文件名不一致的回归测试先失败、修复后通过；解析完成事件统一为 `document_parse_complete`，并写入实际 `parser` 字段，不再把 PaddleOCR 误标成 MinerU。
- 后端完整测试 558 项通过；`ruff check . --select F` 通过。真实 PaddleOCR 外部请求未在本轮重放，避免重复处理用户资料；路由由默认 Parser 定向测试覆盖。

## 2026-09-27 快速入口回归补充

- 根因：材料上传进入 DeerFlow 时，Backend 对空 `message` 的默认请求写成“请根据上传资料识别我的意图”，与用户已选择的快速入口冲突；此前仅在 metadata 中传递 `intent_hint`，没有把动态入口选择明确送入 Agent 用户消息。
- 修复：Backend 只把本轮已确认的快速入口作为动态请求上下文传入；“附件不得重分类、除非用户明确改道”和“默认简体中文”写在科创 Agent SOUL，文档解析与客户拜访 Skill 明确附件必须沿用已选业务流程。上传原文仍使用不可信资料边界。
- 验证：新增客户拜访快速入口回归测试；修复前测试失败，修复后材料流、会话和 DeerFlow 适配定向测试共 71 项通过，相关 Ruff 检查通过。
- 未重启用户运行的 Backend，也未用真实上传和在线模型做端到端验证；代码需在 Backend 重新加载后生效。
