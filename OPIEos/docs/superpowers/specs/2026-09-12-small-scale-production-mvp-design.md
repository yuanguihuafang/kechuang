# 小规模线上生产 MVP 设计

## 背景与目标

本设计把 OPIE OS 部署为面向约 20 个用户的小规模线上版本。用户通过管理员创建的一次性邀请链接注册；每个用户的对话、运行记录、文件、记忆、自定义 Agent、定时任务和流式事件必须相互隔离。部署采用单台云服务器运行 Docker Compose，PostgreSQL 和 Redis 使用托管服务，Agent 工具执行使用独立 Sandbox 容器。

第一版成功标准：

- 支持约 20 个注册用户。
- 全局支持 8～10 个并发 Agent 运行，每个用户最多 2 个并发运行。
- 单次运行最长 10 分钟。
- 没有有效邀请的用户不能注册。
- 用户不能读取、修改、删除或订阅其他用户的任何资源。
- Gateway 重启后历史数据仍可读取。
- PostgreSQL 和用户文件均有备份，并完成至少一次恢复演练。

## 范围与非目标

### 第一版范围

- 管理员手动创建、复制、撤销邀请链接。
- 邀请链接一次性使用，默认 72 小时过期。
- PostgreSQL 作为生产数据库。
- Redis 作为流事件桥接、限流和必要的短期状态存储。
- Gateway 单实例、单 Worker。
- 独立 Sandbox 容器，沿用现有 Sandbox 权限策略。
- HTTPS、固定密钥、生产配置、资源配额、基础监控、备份和恢复。
- 双用户越权测试、20 用户并发测试、重启恢复测试和 Sandbox 安全测试。

### 非目标

- 自动邮件发送邀请。
- 多租户、复杂 RBAC、SCIM、计费和商业化套餐。
- Gateway 多副本和跨区域容灾。
- DLP、敏感信息自动识别和自动脱敏。
- 完整的企业管理后台。

## 部署架构

```text
公网
  ↓ HTTPS
云服务器入口（Caddy 或云负载均衡）
  ↓
Nginx
  ├── Frontend
  └── Gateway（单实例、单 Worker）
        ├── 托管 PostgreSQL
        ├── 托管 Redis
        └── 独立 Sandbox 容器服务
```

云服务器只暴露 HTTPS 入口。Gateway、Sandbox 管理接口、数据库和 Redis 不暴露公网。应用使用独立的内部 Docker 网络；Sandbox 只获得当前用户当前线程所需的用户数据目录。

Gateway 初期固定为单 Worker。当前运行管理、取消、去重等状态仍主要由单进程运行时维护；20 个用户的目标通过异步执行和 Sandbox 并发控制满足，不通过增加 Gateway Worker 实现。

PostgreSQL 使用托管服务并启用 TLS、备份和连接限制。Redis 使用托管服务并启用认证与 TLS，作为流事件桥接、注册/登录限流及短期协调状态存储。

## 用户注册与认证

### 邀请流程

1. 管理员在管理入口创建邀请，输入用户邮箱。
2. 服务生成不可预测的一次性邀请 Token。
3. 管理员复制邀请链接并通过外部渠道发送给用户。
4. 用户打开链接，服务端校验 Token 未使用、未撤销且未超过 72 小时。
5. 用户设置密码并完成注册，邀请立即标记为已使用。
6. 无效、过期、已使用或已撤销的邀请不能创建账号。

邀请记录至少包含：Token 哈希、目标邮箱、创建者、状态、过期时间、使用时间、使用用户和撤销时间。数据库只保存 Token 哈希，不保存可直接复用的原始 Token。邀请创建、撤销和使用写入审计日志。

### 认证边界

- 沿用现有 JWT HttpOnly Cookie、CSRF 和用户上下文机制。
- 服务端从认证上下文解析 `user_id`，不接受客户端声明的 `user_id` 或 `owner_id`。
- 管理员接口要求 admin 身份。
- 注册、登录、邀请创建和密码重置使用 Redis 或入口网关限流。
- 固定并安全保存 `AUTH_JWT_SECRET` 与 `BETTER_AUTH_SECRET`。

## 数据隔离

用户隔离覆盖以下对象：

- Thread 和消息历史
- Run 和运行事件
- SSE 流及断线重连数据
- 上传文件、工作区和输出文件
- Memory
- 自定义 Agent 和 Skill 数据
- Scheduled Task
- 子 Agent 任务

所有读、写、删除和下载路径均必须经过服务端 owner 校验。资源不存在或不属于当前用户时，返回 404 或 403，不泄露其他用户资源是否存在。客户端提交的身份字段会被忽略或拒绝。

隔离验收至少覆盖：直接替换 Thread/Run/Task ID、猜测文件路径、重放下载 URL、订阅其他用户 SSE、修改 `user_id`/`owner_id`/`is_internal` 字段，以及 Gateway 重启后的再次访问。

## Sandbox 安全边界

线上不使用本机 Host Bash 作为安全边界，保持当前 `allow_host_bash: false` 和用户数据虚拟路径设计。每个任务通过独立 Sandbox 容器执行。

Sandbox 约束：

- 只挂载当前用户当前线程所需的 `/mnt/user-data` 数据。
- 不挂载宿主机敏感目录。
- 不访问 PostgreSQL、Redis、Gateway 管理端口或 Docker API。
- 默认禁止入站连接。
- 允许已有配置所需的公网出站访问，但阻断私网、宿主机和云实例元数据地址。
- 限制 CPU、内存、PID、临时磁盘、输出大小和最长执行时间。
- 设置全局 Sandbox 并发上限，任务结束后清理临时容器。

Gateway 不直接持有宿主机 Docker Socket；若 Sandbox Provisioner 需要容器创建权限，应由独立 Provisioner 服务承接，并通过内部 API Key 访问。

## 配额与资源保护

第一版默认配额：

- 单用户最多 2 个并发 Agent 运行。
- 全局最多 8～10 个并发 Agent 运行。
- 单次运行最长 10 分钟。
- 限制单文件大小和每用户文件空间。
- 限制注册、登录失败、邀请创建、API 和 MCP 调用频率。
- 记录模型、输入 Token、输出 Token、运行时长和错误原因。
- 支持每日 Token 上限，超出后拒绝新的模型调用。

## 持久化、监控与恢复

- `database.backend` 使用 PostgreSQL。
- `run_events.backend` 使用 `db`，不使用生产内存存储。
- PostgreSQL 自动备份并加密，保留 7～30 天。
- `.deer-flow` 用户文件、配置和运行所需持久化目录纳入备份。
- 监控 Gateway、PostgreSQL、Redis、Sandbox、CPU、内存、磁盘、5xx、任务超时、活跃运行数和 Token 使用量。
- 日志统一携带 `user_id`、`thread_id`、`run_id`，不记录密码、Token 或模型密钥。
- 上线前完成数据库、用户文件和应用重启恢复演练。

## 验收计划

### 注册与权限

- 无邀请不能注册。
- 邀请只能使用一次，过期和撤销后不可使用。
- 普通用户不能创建或撤销邀请。
- Alice 和 Bob 之间无法互读、互改、互删任何资源。

### 并发与稳定性

- 20 个测试用户同时登录。
- 8～10 个任务并发运行。
- 同时上传文件并保持 SSE 连接。
- Gateway 重启后历史数据和用户归属保持正确。
- Redis、PostgreSQL、模型服务或 Sandbox 短暂异常时，任务以可识别的失败状态结束。

### 发布

- Staging 使用固定镜像版本完成 Smoke Test。
- 生产部署前备份数据库和用户文件。
- 发布后观察 24～48 小时，再决定是否扩大用户范围。
- 保留上一版本镜像和回滚配置。
